# #9 饮食算法基线（Issue #9）

负责人：张洋（`hydrazZYT`）｜数据集：`issue10-dinner-v1@0.1.1`｜场景包：`diet-scene-pack-0.1.0`｜算法：`local-rules-0.1.0`

本文固定 #9 的输入、预期输出、依据版本与耗时口径，供 #10 换算法后重放对照。机器可读基线见 [`docs/testing/issue10/algorithm-baseline.json`](../testing/issue10/algorithm-baseline.json)。

## 1. 本版选型

| 环节 | 本版方案 | 备选方案 | 选择依据 |
| --- | --- | --- | --- |
| 抽取 | 本地词表、别名与句式规则，离线覆盖饮食文本 | 经 `InferencePort` 接获准模型 API，返回同构结构化候选 | 首版要求空库离线可走完整流程；规则结果可复现、无远程调用量。模型候选只作标签补充，可直接计算的事实字段仍以规则为准。 |
| 偏好归并 | 按事件归并键去重，两次独立实际经历形成推断偏好；本人明确设置优先 | 特征与权重版本化的在线逻辑回归 | 样本量不足以训练回归；规则计分可解释、可核对依据。逻辑回归保留为下版增量参数候选（见系统设计 §6.2）。 |
| 排序 | 先按预算等显式条件硬筛选，再按命中条件与有效证据计分 | 在线逻辑回归排序 | 候选少、条件透明；明确规则未命中时不参与加权，推断偏好只作低风险背景。 |

## 3. 预期输出基线

### 3.1 计数与条件

| 断言 | 预期 |
| --- | --- |
| 独立加班晚餐经历 | 2（E01、E02） |
| 周末例外 | 1（E03） |
| `weekday_overtime_convenience` 支持次数 | 2 |
| D01 后支持次数 | 仍为 2，可新增来源，不新增事件 |
| R01 | `observationType=reported`，本人偏好与计数不变 |
| C01 范围 | 工作日（mon–fri）且加班，倾向 `convenience` |
| Q03 | 明确规则未命中（`scopeMatch=false`），不套用省事规则 |
| Q01b | 明确规则命中（`scopeMatch=true`），优先省事 |

### 3.2 候选菜单与排序

| 候选 | 价格(元) | 备菜/制作(分钟) | 需洗锅 | 省事分 |
| --- | ---: | ---: | ---: | ---: |
| rice-bowl 盖饭 | 16 | 10 | 否 | 9 |
| noodle-soup 热汤面 | 18 | 10 | 否 | 9 |
| bento 轻食便当 | 19 | 5 | 否 | 8 |
| stirfry 家常炒菜 | 15 | 35 | 是 | 3 |
| tomato-egg-noodle 番茄鸡蛋面 | 20 | 40 | 是 | 2 |
| hotpot 麻辣烫 | 22 | 15 | 是 | 5 |

各用例预期顺序（预算外的 `hotpot` 一律硬筛掉）：

| 用例 | 预期顺序 | 引用证据 |
| --- | --- | --- |
| Q01 | rice-bowl → noodle-soup → bento → stirfry → tomato-egg-noodle | E01、E02 |
| Q02 | tomato-egg-noodle → stirfry → bento → rice-bowl → noodle-soup | E03 |
| Q03 | rice-bowl → noodle-soup → bento → stirfry → tomato-egg-noodle | 无明确规则引用 |
| Q01b | rice-bowl → noodle-soup → bento → stirfry → tomato-egg-noodle | E01、E02 |

同一输入连续跑三次，候选顺序必须一致；顺序波动记为不稳定。

## 4. 耗时与调用量

- 调用量：本版本地规则，每次查询远程模型调用 `0` 次。
- 耗时：`extract / update / rank` 分段计时，同一输入跑三次取均值，由 CI 或首测机实测后回填基线 JSON 的 `latencyMillis`；当前不预填数值。
- 预算口径沿用系统设计：一次文本整理或查询最多 3 次模型调用、每次输入最多 4,096 token；本地规则不占用远程预算。

## 5. 版本与重放

- 场景包、词表、候选菜单或排序规则变化时，递增对应版本，重跑 G01–G12 并保留新旧结果对照。
- 换抽取模型或排序方法时，先用相同材料重放新旧实现，比较标签命中、引用正确性、建议顺序、耗时与调用量；出现回归可切回上一版并用有效证据重算。
- 证据回查按 `sourceId`、`sourceVersion` 与码点区间取回原话；来源失效时单独显示原因，不补造引文。
