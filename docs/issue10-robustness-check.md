## 一、验收输入

使用两次独立晚餐经历和一条重复分享作为固定输入：

1. 工作日加班，预算二十元，希望少洗几个碗；最后吃了热汤面。
2. 周末时间充裕，愿意慢慢做饭；最后做了两菜一汤。
3. 将第一条经历通过系统分享重复送入一次，确认不重复计数。
4. 增加一条转述材料，确认来源定位与真实经历分开保存。
5. 将“加班时优先省事”改为“只在工作日加班时优先省事”，再重新提问。

## 五、健壮性与异常检查

| 编号 | 异常场景 | 预期处理 | 实际结果 |
| --- | --- | --- | --- |
| R01 | 空文本/全空白 | 拒绝保存并保留输入 | 通过 |
| R02 | 连续双击保存 | 返回同一回执，只产生一条记录 | 通过 |
| R03 | 存储写入失败 | 原记录和草稿保留，提示失败原因 | 通过 |
| R04 | 数据库锁竞争 | 写入串行等待或明确失败，不产生半条记录 | 通过 |
| R05 | 应用进程被回收 | WorkManager/任务表恢复，不重复发布阶段结果 | 通过 |
| R06 | 算法暂时不可用 | 进入等待状态，恢复后重试 | 通过 |
| R07 | 用户取消 | 不再产生新的结果或后继任务 | 通过 |

## 六、测试结论

- 契约字段、任务阶段和可执行操作在页面与核心之间保持一致。
- 固定输入下算法输出顺序、依据引用和纠正后的结果符合预期。
- 重复保存、进程中断、偏好纠正与旧任务迟到四类关键健壮性场景均通过。
- 未发现“已确认保存的记录丢失”“旧任务覆盖新纠正”“重复执行产生第二份结果”等阻断问题。
- 本轮未覆盖其他 Android 机型、极端低存储空间和长时间 Doze 状态，后续候选 APK 继续回归。
